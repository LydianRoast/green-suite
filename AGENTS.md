# Public writing and data handling

Use neutral, professional language in public documentation, application text
and commit messages. Describe implemented capabilities, operation, development
and verified limitations. Identify planned or unverified features clearly.

Keep personal instructions, conversation or session logs, customer and project
identifiers, credentials, private paths and machine-specific setup details out
of public source and its history. Use synthetic data and portable examples.

Preserve required copyright notices, licenses, contributor and source
attribution, protocol facts and compatibility identifiers. Privacy cleanup must
not silently change application behavior or remove required attribution.

Review both the current tree and every outgoing historical revision. Removing
content from the latest file does not remove it from earlier commits. Maintain
private recovery copies separately from published references.
